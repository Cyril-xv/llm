# Redis 核心原理与实践指南

## 一、什么是 Redis

Redis 是一款开源的基于内存的高性能键值存储数据库，通常被称为数据结构服务器。它的读写性能极高，单机可以支撑每秒十万级别的读写操作，被广泛用作缓存、消息队列、分布式锁和排行榜等场景的底层存储。Redis 的所有数据都存储在内存中，但可以通过持久化机制把数据保存到磁盘，重启后恢复。

Redis 是单线程模型执行命令的，这里的单线程指的是命令执行阶段，它通过事件循环和 IO 多路复用技术同时处理大量客户端连接，避免了多线程上下文切换和锁竞争的开销，这也是它性能高的关键原因之一。后续版本虽然引入了多线程处理网络 IO，但命令的执行依然保持单线程语义。

## 二、Redis 的五大基础数据结构

String 是最基础的数据类型，可以存储字符串、整数、浮点数，常用于缓存对象、计数器、分布式锁的 value 等场景。List 是双向链表，支持从两端压入弹出，适合做消息队列、时间线等先进先出或后进先出的场景。Hash 存储键值对映射，适合存储对象字段，可以单独更新某个字段而不影响其他字段。Set 是无序去重集合，支持交并差运算，适合做标签、好友关系、去重统计。ZSet 是有序集合，每个元素带一个分值，按分值排序，适合做排行榜、延迟队列、限流等场景。

除了五大基础结构，Redis 还提供了 Bitmap、HyperLogLog、Geo 等高级数据结构，分别用于位图统计、基数估算和地理位置计算。

## 三、Redis 持久化机制：RDB 与 AOF

RDB 是快照持久化，在指定的时间间隔内把内存中的数据生成二进制快照写入磁盘，恢复速度快，适合数据备份和灾备恢复，但可能丢失最后一次快照之后的数据。RDB 由子进程完成生成，通过写时复制技术不阻塞主进程的写操作。

AOF 是追加日志持久化，每执行一条写命令就把命令追加到日志文件末尾，通过配置 appendfsync 控制刷盘策略，包括每秒同步、每命令同步和不主动同步三种模式。AOF 的优点是数据丢失少，缺点是文件体积大、恢复速度慢。AOF 文件会随着时间膨胀，通过重写机制压缩文件体积。

实际生产通常两者配合使用：开启 RDB 做备份，开启 AOF 保证数据安全，Redis 重启时优先加载 AOF 文件。

## 四、缓存过期与淘汰策略

Redis 的过期删除策略是惰性删除加定期删除的结合。惰性删除指访问 key 时才检查是否过期；定期删除指后台每隔一段时间抽样删除部分过期 key。两者结合保证过期 key 不会被长期占用内存。

当内存写满达到 maxmemory 限制时，Redis 触发内存淘汰策略，常见的包括：noeviction 不淘汰直接报错、allkeys-lru 对所有 key 按最近最少使用淘汰、volatile-lru 只对设置了过期时间的 key 按最近最少使用淘汰、allkeys-lfu 按最少频率使用淘汰、random 随机淘汰等。生产环境一般选择 allkeys-lru 或 allkeys-lfu。

## 五、缓存穿透、缓存击穿与缓存雪崩

缓存穿透指查询一个不存在的 key，缓存和数据库都没有，请求直接打到数据库，恶意攻击可以利用这一点拖垮数据库。解决办法是缓存空值，或使用布隆过滤器在缓存前拦截不存在的 key。

缓存击穿指某个热点 key 过期瞬间，大量并发请求同时打到数据库。解决办法是热点数据设置永不过期加异步更新，或使用互斥锁保证只有一个请求去重建缓存。

缓存雪崩指大量 key 在同一时间集中过期，或 Redis 服务宕机，导致请求全部打到数据库。解决办法是给过期时间加随机抖动，避免集中过期，多级缓存降级，以及 Redis 高可用部署。

## 六、分布式锁的实现

Redis 实现分布式锁最常见的方案是基于 SET 命令加 NX 和 EX 参数，一次性完成加锁和设置过期时间，避免死锁。加锁时 value 使用唯一的客户端标识，释放锁时先比较 value 再删除，用 Lua 脚本保证比较和删除的原子性，防止误删他人的锁。

在高可用场景下，简单的单机锁存在主从切换后锁丢失的风险，Redisson 提供了看门狗机制自动续期，RedLock 算法可以跨多节点加锁提高安全性。分布式锁的时间不宜过短，以免业务未执行完锁就过期，也不宜过长，影响并发性能，需要根据业务耗时合理设置。

## 七、Redis 高可用：主从复制、哨兵与集群

主从复制通过从节点异步复制主节点的数据，实现读写分离和故障恢复。主节点负责写，从节点负责读，从节点通过全量同步加增量同步保持数据一致。

哨兵模式在主从复制基础上增加哨兵节点，监控主节点的健康状态，主节点故障时自动选举新主节点完成故障转移，对客户端透明。哨兵至少部署三个节点，避免脑裂问题。

集群模式将数据分片存储到多个主节点，每个主节点带若干从节点，通过哈希槽分配数据，支持水平扩展，可以支撑更大的数据量和更高的并发。集群模式下客户端需要支持重定向逻辑。

## 八、Redis 作为消息队列

Redis 可以承担轻量级消息队列的职责。List 结构通过阻塞弹出命令实现简单的队列，支持多个消费者。Stream 是 Redis 5.0 引入的专门消息队列结构，支持消费者组、消息确认和待处理消息列表，可以做到消息不丢失。对于消息可靠性要求极高的场景，建议使用专业的消息中间件，Redis 消息队列更适合轻量级、低延迟的内部通信。

## 九、Redis 与 MySQL 的一致性

使用 Redis 作为 MySQL 的缓存层时，写入操作常见的策略是先更新数据库再删除缓存，配合缓存过期时间兜底，尽量避免缓存与数据库长期不一致。延迟双删、消息队列异步删除是常用的补偿手段。缓存一致性无法做到强一致，业界普遍接受最终一致性，核心是保证缓存过期时间内的短暂不一致可接受。

## 十、Redis 常见使用场景总结

热点数据缓存加速是最广泛的应用，配合过期策略和淘汰策略使用。分布式锁解决多实例下的并发控制。排行榜使用 ZSet 实时计算排名。计数器使用 INCR 命令实现浏览量、库存扣减。会话保持把用户登录态存入 Redis。限流通过固定窗口或令牌桶算法实现。布隆过滤器防止缓存穿透。以上场景共同构成了 Redis 在互联网后端系统中的核心地位。
